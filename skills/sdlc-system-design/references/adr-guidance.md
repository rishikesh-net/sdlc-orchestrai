# ADR guidance
Write an ADR when a decision is expensive to reverse, affects several teams/modules, introduces new
technology, or sets a security/data boundary. Number sequentially: `docs/adr/0001-title.md`.
Status flow: Proposed -> Accepted -> (Superseded by ADR-NNNN | Deprecated). Never edit an accepted
ADR's decision; supersede it. Keep each ADR under one page and always list at least one rejected alternative.
